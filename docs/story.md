# Ретроспектива решения

## Abstract

В процессе решения кейса пробовались разные решения: Classic ML, берты, RAG pipeline.
Остановиться было решено на последнем - это решение хоть и тривиальное,
однако более интерпретируемое и адаптивное к изменениям внешней среды.

## Classic ML

Для задачи shoul split использовались архитектуры Logistic Regression, Random Forest, HistGradientBoosting, CatBoost, XGBoost, LightGBM.
Для задачи разделения на микрокатегории использовались OneVsRest Logistic Regression, OneVsRest XGBoost, OneVsRest Random Forest.
Обучение проводилось на исходном датасете и на расширенном датасете сгенерированном через Mistral. 
Сравнивались метрики (в частности f1) и для лучшей модели проводилась оптюна.


## BERT

Сначала BERT использовался как эмбеддер, метрики не выросли (относительно эмбеддера FRIDA). 
Дообучал bert модель на задачу определения микрокатегорий, метрики были выше чем у OneVsRest архитектур


## RAG pipeline

После апдейта датасета прошлые методы стали хуже работать | перестали работаь вовсе.
Поэтому было решено попробовать сделать обычный пайплайн с LLM и RAG retrieval.
Также при разработке *возникали вопросы* к новому датасету, т.к. были найдены сэмплы, на которые даже разработчики не
смогли ответить.
Поэтому этот датасет не использовался для RAG, он был полностью автоаннотирован большой `mistral-large` моделью и уже
эта версия используется в RAG.

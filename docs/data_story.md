# Changelog используемых в методологии подходов

## 28.03.2026 - 03.04.2026

### Abstract

- Бейзлайн кейсхолдера: LR на хуках с модели
- Первая гипотеза: можно улучшить бейзлайн, обучив бустинги на хуках
- С модели было взято больше 1600 фич с разных блоков: attention, moe output и т.д.
- Датасет: датасеты бенчмарка russiannlp/tape (CheGeKa, MultiQ), RuBQ2.0 в равном соотношении. Итого с аренды сервера с
  A100 вышел датасет на 1391 семпла

### 1. Бейзлайн на хуках с модели: LR на хуках с модели - 0.7638 average precision

Изначально обучить какую-то легкую модель на фичах из модели, казалось перспективным решением, учитывая количество
фичей, которые можно было извлечь. Гипотеза о том, что можно обучить модель более сложную, чем LR, на этих фичах, была
логичной, учитывая их количество и разнообразие.

### 2. Первая гипотеза: можно улучшить бейзлайн, обучив бустинги на хуках - 0.7718 average precision

В качестве исследуемых моделей были выбраны CatBoost, LightGBM, XGBoost. Все модели обучались на кастомном миксе
датасетов выше в равном соотношении. Так же модели тюнились через optuna, чтобы выжать из них максимум.
Результаты оказались сильно хуже бейзлайна: weighted accuracy 0.25 у наименьшего класса (не галлюцинация).
Команде не хватило экспертизы для эффективного представления признаков, поэтому от решения
"внутренней" детекции галлюцинаций было решено отказаться.

### 3. Конфигурация признаков

Подробнее `configs/sber/hooks_config.yaml`, `scripts/extract_features.py`, `src/models/extract_features.py` [LEGACY]
ПРИМ. Для извлечения признаков необходимо было арендовать VPS с A100 (конфигурация машины кейсхолдера),
что также осложняло процесс расширения датасета для данного подхода, т.к. извлечение хуков требует инференса через
Torch, что не является оптимизированным процессом.

### 4. Датасет

В качестве датасета обучения (для валидации использовался паблик тест [не для гипотезы 1]) был выбран микс из
датасетов, исследующих фактологические знания модели: CheGeKa, MultiQ, RuBQ2.0. Датасеты были взяты в равном
соотношении, что позволило создать более сбалансированный датасет для обучения моделей.
В качестве входного промпта к модели был использован вопрос из бенчмарка в чистом виде, **без дополнительных инструкций
**.
Ответы модели также **не были** отформатированы.
При генерации ответов динамически изменялась температура от 0 до 1.7 по Гауссову распределению для получения более
разнообразных ответов от модели.
Итоговые статистики датасета: 1391 семпл, 1600+ внутренних фичей модели, распределение 24/76 по классам (не
галлюцинация/галлюцинация). Определением правильности ответа занималась LLM `mistral-small-latest` (подробнее
`notebooks/[DATASETS] Auto-Annotations.ipynb`) Это решение спровоцировано ограниченностью ресурсов для ручной разметки.

### Abstract

- Вторая гипотеза: "сгаллюцинированное" в ответе модели более заметно в его текстовых признаках, чем в числовых фичах из

- Демо: для демонстрации работы была написана демка на gradio
- Третья гипотеза: обученные под NLI задачу берты могут эффективно выявлять галлюцинации в ответах модели

### 1. Вторая гипотеза: "сгаллюцинированное" в ответе модели более заметно в его текстовых признаках, чем в числовых фичах из модели

При обучении моделей (бустинги, LogReg, леса и т.д.) были добавлены текстовые статистические признаки (см.
`notebooks/sber/[TRAIN] Tabular staff.ipynb`), метрика почти не изменилась

### 2. Демо: для демонстрации работы была написана демка на gradio

Для демонстрации работы модели была написана демка на gradio, которая позволяет пользователю ввести вопрос и получить
ответ от модели, а также оценку вероятности галлюцинации и время работы каждого из этапов.

### 3. Третья гипотеза: обученные под NLI задачу берты могут эффективно выявлять галлюцинации в ответах модели

Для проверки данной гипотезы были обучены модели на основе BERT, которые были натренированы на задачу NLI (Natural
Language Inference). Результаты не превосходили бейзлайн, при своей тяжеловесности относительно бустингов и
логистической регрессии.
